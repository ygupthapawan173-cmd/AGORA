# JARVIS AI v0.2.0 — Feature Specification

## Product direction
A Telugu + English Android personal assistant with a futuristic red / black / white interface. Default behavior is free-first; explicitly selecting OpenAI may incur separate API charges. Device actions require a separate preview and user approval.

## Implemented in source (not yet device-verified)

### Interface
- New JARVIS robot dashboard and Home / Chat / Voice / Agent / Settings navigation.
- Red / black / white panels, glowing accents, animated voice waveform and original in-app vector robot artwork.
- Dedicated screens for AI providers, voice, agent planning, accessibility, memory, reminders, vision and files.

### AI brain
- Gemini, OpenAI and optional local llama.cpp provider selection.
- Auto mode uses Gemini when configured; otherwise attempts the local provider. It never silently selects the billable OpenAI API.
- Gemini text / image requests and OpenAI Chat Completions text requests.
- Provider API keys are encrypted at rest using Android Keystore. Mobile client-side storage is not a backend secret store; device owners/reverse engineers may still extract keys.
- The optional local provider expects an OpenAI-compatible llama.cpp endpoint at `http://127.0.0.1:8080` on the same Android device.

### Conversation and voice
- Local conversation memory with view, clear and manual export controls.
- Android speech input with Auto / Telugu / English (India) selection.
- Android TTS replies with best-effort installed male / female voice selection.
- `Hey Jarvis` speech-recognizer wake loop with foreground-service notification and explicit stop control.

### Agent and phone tools
- AI-generated task plan preview; plans are informational and do not claim to have executed tasks.
- Separate preview + approval for supported Android intent commands.
- Calls open the dialer; SMS opens a composer and is never silently sent.
- App launch, search, Settings and Camera intents.
- Local reminders using `AlarmManager.setAndAllowWhileIdle`; Android may defer delivery, and notification permission is required on Android 13+.

### Vision and documents
- User-selected image or camera still analysis through Gemini.
- Local text extraction from PDF, DOCX, XLSX, TXT, MD, CSV, JSON and XML before the user chooses to send the extracted text to the configured chat provider.
- Scanned/image-only PDFs are not OCR processed by this document reader.

### Accessibility — Selected Apps Only, cloud sharing OFF
- Allowlist starts empty; user selects launcher apps explicitly.
- Package filtering and conservative exclusion of common banking / wallet / payment app name patterns.
- Local screen text snapshot held in service memory only; it is not sent to Gemini, OpenAI or local AI and is not persisted.
- One-time user-approved Back, Scroll up/down, Swipe left/right/up/down and exact visible-label Click.
- Action is bound to the selected package, a 30-second window and the same screen snapshot; changed/expired screens fail closed.
- Password / OTP / PIN / CVV heuristics block snapshots and actions. These heuristics are not exhaustive; never use the feature on sensitive apps/screens.
- Pause / Resume; action metadata-only audit log. Click labels and screen text are not saved to the log.
- Android Settings enablement is user-controlled; in-app disclosure explains local-only scope.

## Not implemented / later release work
- Native full-duplex GPT Live / Gemini Live streaming voice sessions.
- Dedicated offline wake-word engine; current wake phrase uses Android SpeechRecognizer, whose availability/network behavior depends on the device.
- Bundled on-device LLM and offline Telugu ASR/TTS models. Local AI requires a separate Termux llama.cpp server/model.
- Continuous live camera/video understanding; only still images are supported.
- True autonomous multi-step execution and arbitrary app workflows. Agent plans are previews; device actions remain explicitly approved and limited.
- Persistent reminder management (edit/delete/repeat) and exact alarm guarantees.
- Server-side secure API proxy, provider billing caps and enterprise key isolation.
- Comprehensive app/device QA, automated UI tests, and Google Play accessibility declaration/review.

## Security and release notes
- Do not use Accessibility on banking, wallet, payment, password manager, OTP, or authentication screens.
- The privacy heuristics are protective signals, not a security guarantee.
- Accessibility API use must comply with current Google Play policy, disclosure, consent, and declaration requirements before Play distribution.
- A successful CI build is not proof of on-device voice, permission, alarm, or Accessibility correctness.
